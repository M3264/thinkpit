Key cost drivers are user count, feature depth, and support needs.
**Evidence needed**
- Historical churn or retention rates for flat subscriptions of similar size.
- Peak and average API/feature usage per user to estimate usage‑based billings.
- Customer acquisition cost versus lifetime value under each model.
- Competitor pricing structures for comparable niche tools.

**Assumptions**
- Users will consistently engage in a pattern that can be forecasted.
- Infrastructure cost scales linearly with usage volume.
- No hidden CAC spikes from a sudden shift to usage billing.

If user churn is low and usage is predictable, a flat fee offers simplicity. If usage varies wildly, usage billing aligns cost with risk and can protect margins.

For 200 weekly users, a flat fee keeps revenue predictable and requires less billing overhead. Usage billing only makes sense if per‑user consumption varies widely and the cost of additional usage is non‑trivial compared to the flat fee’s fixed cost. Evidence that would shift the choice includes:

* Actual peak vs average feature/API usage per user
* Incremental infrastructure cost per usage unit
* Historical churn during pilot periods for both models
* Customer willingness to respond to fluctuating bills

Assumptions that may bias a flat‑fee preference are linear cost scaling and stable user engagement; real‑world growth or feature drops can invalidate those.
